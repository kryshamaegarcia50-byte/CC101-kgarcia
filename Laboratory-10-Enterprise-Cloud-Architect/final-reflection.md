# Final Reflection

Looking back at the ten missions, I can see how much my confidence has grown. In Mission 1, I was only learning to use the Linux terminal in KillerCoda and to save my work in GitHub. The Markdown files I wrote then felt like a small task, but they taught me that clear documentation is a real part of an engineer's work.

Missions 2 and 3 helped me understand what the cloud is made of. I checked the CPU, memory, disk, and network of a real Linux server, then compared AWS, Azure, and GCP and chose the best platform for different clients. This showed me that cloud engineers must pick tools to fit the problem, not just choose the most popular one.

Missions 4, 5, and 6 were about building. I ran my first Docker container, set up MinIO object storage, and used Docker Compose to start a web application and its database with one command. I learned that containers start in seconds, that volumes protect data, and that writing a configuration file is more reliable than typing commands by hand.

In Missions 7, 8, and 9, I learned how to keep a system healthy. Logs and metrics showed me what the server was doing, the UFW firewall limited access to only the ports that were needed, and a Bash script with cron made backups happen without anyone remembering to do them.

Mission 10 combined all of this into one project. We prepared a VirtualBox server, deployed WordPress and MariaDB, secured it, and automated its backups. The hardest part was making every layer work together, and the problem solving from earlier missions, like finding another image when one could not be pulled in Mission 5, prepared us for it.

Overall, this course taught me that cloud computing is not only about technology. It is about planning carefully, protecting data, automating routine work, and writing documentation that others can follow. My GitHub portfolio now shows that journey from the first Linux command to a complete cloud project, and I am ready to keep learning from here.
